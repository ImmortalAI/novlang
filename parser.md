# NovLang — промпт для планирования реализации

Это отправная точка для отдельной директории/репозитория с библиотекой **NovLang**.
Ниже — контекст и все решения, принятые при брейнсторминге в проекте
`easy-digital-book`. Используй `superpowers:writing-plans` (или сначала
`superpowers:brainstorming`, если что-то из решённого ниже потребует уточнения),
чтобы составить пошаговый план реализации v1.

## Контекст

NovLang — язык разметки для текстов новелл и библиотека-парсер для него.
Разрабатывается как самостоятельный open-source TypeScript-пакет, независимый
от какого-либо конкретного приложения. Первый (и на момент написания — единственный)
потребитель — редактор `easy-digital-book` (Tauri + Vue 3), который будет
использовать NovLang для live-preview в редакторе и для генерации EPUB, но
сама библиотека НЕ должна иметь зависимостей на Tauri/Vue или какой-либо UI-код.

## Язык и рантайм

- **TypeScript**, публикуется как npm-пакет.
- Работает как в браузере (webview Tauri-приложения), так и в Node — без
  дополнительных тулчейнов (WASM/Rust сознательно отклонены как избыточные
  для этой задачи).

## Грамматика v1

Синтаксис — Markdown-совместимое подмножество там, где это не мешает, плюс
собственные конструкции под нужды новелл. Один файл NovLang = одна глава.

| Элемент | Синтаксис | Пример |
|---|---|---|
| Заголовок главы | `#` один раз в начале файла | `# Глава 12. Пробуждение` |
| Курсив | `*текст*` | `*тихо прошептал он*` |
| Полужирный | `**текст**` | `**ВНИМАНИЕ!**` |
| Сцен-брейк | `***` отдельной строкой | центрированный орнамент между сценами внутри главы |
| Изображение | `![alt](путь)` | `![Обложка главы](images/ch12.png)` |
| Сноска — ссылка | `[^1]` инлайн в тексте | как в Pandoc/Obsidian |
| Сноска — определение | `[^1]: текст сноски` отдельным блоком | |
| Блок-цитата / письмо | `>` в начале каждой строки блока | письма, послания, вставки |
| Абзацы | разделяются пустой строкой | как в обычном Markdown |
| Экранирование | `\` перед спецсимволом | `\*не курсив\*` |

Метаданные книги (название, автор, обложка, порядок глав) в грамматику
NovLang НЕ входят — они живут на уровне приложения-потребителя (в файле
манифеста контейнера книги). NovLang парсит только содержимое одной главы.

## Архитектура

Два независимых слоя:

1. **Parser** — `parse(source: string) => { document: NovLangDocument, diagnostics: Diagnostic[] }`.
   Превращает текст в дерево типизированных узлов, без какого-либо HTML на
   этом этапе.
2. **Renderer** — `renderToHTML(document: NovLangDocument, options?: RenderOptions) => string`.
   Превращает AST в разметку. Один и тот же renderer используется и для
   live-preview в редакторе, и для генерации XHTML внутри EPUB — для второго
   случая нужен флаг `xhtmlMode` (самозакрывающиеся теги и прочие требования
   строгого XHTML).

Черновой набросок типов AST (уточнить/доработать при планировании):

```typescript
type Diagnostic = {
  severity: "warning";
  message: string;
  position?: { line: number; column: number };
};

type InlineNode =
  | { type: "text"; value: string }
  | { type: "emphasis"; children: InlineNode[] }
  | { type: "strong"; children: InlineNode[] }
  | { type: "image"; alt: string; src: string }
  | { type: "footnoteRef"; id: string };

type BlockNode =
  | { type: "heading"; children: InlineNode[] } // заголовок главы, один раз в начале документа
  | { type: "paragraph"; children: InlineNode[] }
  | { type: "sceneBreak" }
  | { type: "blockquote"; children: BlockNode[] } // письма/цитаты — блок из параграфов
  | { type: "footnoteDef"; id: string; children: BlockNode[] };

type NovLangDocument = {
  type: "document";
  children: BlockNode[];
};

interface RenderOptions {
  xhtmlMode?: boolean; // true — для XHTML внутри EPUB
}
```

**Дополнительно проверить при планировании:** для сносок в режиме `xhtmlMode`
стоит рассмотреть разметку в духе EPUB3 footnotes (`epub:type="noteref"` /
`<aside epub:type="footnote">`), чтобы на Kindle сноска открывалась всплывающим
окном, а не прыжком в конец главы. Это не обязательное требование v1, но
качественно улучшает читательский опыт почти бесплатно — стоит оценить
трудозатраты в плане.

## Обработка ошибок

Библиотека никогда не должна бросать исключения на "плохом" вводе — это
инструмент для писателя, а не компилятор. Примеры желаемого поведения:

- Незакрытый `*` — рендерится как обычная звёздочка (не ломает парсинг).
- Ссылка на неопределённую сноску `[^1]` — рендерится видимым маркером.
- Все подобные случаи собираются в список `diagnostics`, возвращаемый вместе
  с деревом, чтобы потребитель (например, редактор) мог подсветить
  предупреждения inline, не прерывая работу пользователя.

## Тестирование

- **Vitest**.
- Юнит-тесты на каждое правило грамматики: input → ожидаемый AST.
- Snapshot-тесты на renderer: input → ожидаемый HTML/XHTML (включая
  `xhtmlMode`).
- Тестами же фиксируется поведение diagnostics на невалидном вводе
  (перечисленные выше кейсы и подобные).

## Явно вне рамок v1 (YAGNI)

- Никаких других форматов вывода, кроме HTML/XHTML (plain text, LaTeX и т.п. — не сейчас).
- Никакой вложенности сносок (сноска внутри сноски).
- Никакого CLI — это чистая библиотека с публичным API `parse`/`renderToHTML`.
- Никакой поддержки нескольких "диалектов" грамматики — один синтаксис для всех.

## Задача для планирующей сессии

Используя весь контекст выше, составь по `superpowers:writing-plans`
пошаговый план реализации NovLang v1: структуру пакета, порядок работ
(токенайзер/парсер → AST → renderer → diagnostics → тесты), критерии
готовности каждого шага. Если что-то из решённого выше кажется неполным или
противоречивым — сначала проведи короткий брейншторминг для уточнения, а
затем переходи к плану.
